# MediaWiki Gadgets

MediaWiki Gadgets is a local TypeScript workspace for developing, testing, and
building browser tools for MediaWiki sites, primarily Wikipedia.

> **Status:** The gadgets are under active development and have independent
> release cycles.

## Gadgets

- [Citation Formatter][1] formats and manages CS1 citations in MediaWiki source
  editors.
- [VG Page Assessor][2] assesses Chinese Wikipedia video-game talk pages and
  registers eligible pages on the WikiProject new-page list.
- [VG Stub Creator][3] builds and reviews Chinese Wikipedia video-game stub
  articles and their related edits.
- [wikEd Lite][4] formats and highlights wikitext in MediaWiki source editors.

## Build

MediaWiki Gadgets requires Node.js 22.18 or newer. Install the workspace
dependencies and build every gadget:

```shell
npm install
npm run build
```

Each gadget produces two stable, unhashed files under its hyphenated package
directory:

- `dist/<gadget-name>/<name>.min.js`: the minified version; and
- `dist/<gadget-name>/<name>.user.js`: the Greasemonkey-compatible version.

The same build also writes every gadget into one installable userscript at
`dist/mediawiki-gadgets/mediawiki_gadgets.user.js`. Its header uses a UTC build
timestamp as the aggregate version and retains the independent package authors.
Each embedded gadget still runs only on its own declared sites.

Build one gadget with `npm run build -w <gadget-name>`. Its package README
contains installation and use instructions. Build only the aggregate directly
from the current sources with `npm run build:all-userscript`.

## Development

Run the complete workspace checks and build:

```shell
npm run check
npm run build
```

The workspace separates deployable gadgets from shared browser-independent
code:

```text
src/
├── citation-formatter/
├── vg-page-assessor/
├── vg-stub-creator/
├── wiked-lite/
└── shared/
```

Each gadget README is the package entry point for use and development. Its
`AGENTS.md` adds package-specific constraints, and its `CHANGELOG.md` records
release history. Every package README uses the same `Run`, `Features`,
`Development`, `Architecture`, and `License` structure.

Repository-wide architecture and documentation rules live in [AGENTS.md][5].
Action-specific procedures are kept in the [release workflow][6] and [commit
workflow][7].
